# 二手纺机铭牌别名归并

项目短名 `yangfan-loom-alias`。视觉采用黄铜铆接铭牌、深铁黑。

恒汀旧纺设备站 · 六人收购质检组。设备站每周验收约 80 件拆机备件。收购员按照片转写铭牌，质检员拿 Excel 查三套历史台账并核对实物，备件库按签认的规范件号建入库单。本站把台账查找、候选排序和待复核清单放在同一次运行中。

上传合并台账 CSV。历史别名行写已签认的库存件号（字母和数字，可用短划线分段），待验铭牌行在规范件号栏填“待归并”。每行保留记录号、来源批次、铭牌厂牌与铭牌转写。 输出逐张铭牌的候选件号、相似度、分差、命中的历史铭牌和建议件号，供质检员签认并向备件库交接。

- 全角铭牌和现场抄写中的点、空格、短划线让 Excel 精确查找漏掉旧别名。
- GR-381 与 GR-382 同厂且仅差一位，磨损铭牌很容易被误挂到近似件号。
- 仅传件号会丢失命中的旧台账行，备件库退回异常件时要重新翻照片。

## 六个业务模块

1. 收购验件总览
2. 铭牌别名台账
3. 片段编码与检索
4. 同厂候选明细
5. 件号归并签认
6. 备件入库交接

## 工作剧本

1. 08:15，收购班在总览核对 SK-261125-A 的 12 张待验铭牌，重点查看澜浦两件近号零件。
2. 08:40，台账员导入 hengting-261125-plate-ledger.csv，合并 24 条历史别名和 12 张待验铭牌。
3. 09:05，质检员使用 4096 桶和 2–3 字符片段运行，最低相似度设为 0.55，最低候选分差设为 0.08。
4. 09:15，在结果中打开 SK-261125-A-01，核对全角铭牌 ＧＲ－３８１ 与历史记录 DA-LP-GR-381-01 的对应关系。
5. 09:35，复核 SK-261125-A-03 的残缺转写 GR-38，请收购员拍清 GR-381 与 GR-382 的末位；第 12 张德潭铭牌单独补查厂牌。
6. 10:10，签认 9 条建议件号后导出 SK-261125-A 的 12 行明细至备件入库组，3 条拒识行留作复拍和补录。

## 算法与复核

统一全半角与大小写，保留字母和数字。带边界标记的字符片段按固定 BLAKE2b 哈希累计入桶，同厂历史别名用余弦相似度检索，每件号取最高分，再用相似度和候选分差决定是否给出建议。

空台账、记录号重复、类别无效、铭牌有效字符不足或件号漏填时提示修正。无同厂记录、相似度偏低、候选分差偏小或同分时转人工复核。整批没有建议时暂停报告发布。 复核问题为「拟归并的铭牌是否已对照照片核实同厂和件号？其余铭牌是否已安排复拍或厂牌补录？」。每次分析绑定数据版本和参数，原始数据按规范化内容的 SHA-256 去重。日程针对已复核的固定结果版本，每日模式按初次投递时间每 24 小时重复。停机期间错过多次时只补一份到站内收件箱，下一次回到原时间点。

| 字段 | 含义 | 类型 |
|---|---|---|
| `record_id` | 记录号 | str |
| `batch_id` | 来源批次 | str |
| `manufacturer` | 铭牌厂牌 | str |
| `record_type` | 记录类别 | str |
| `plate_text` | 铭牌转写 | str |
| `part_number` | 规范件号 | str |

## 启动

```sh
[ -f .env ] || cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

- Web 界面 `http://127.0.0.1:18370`
- API 文档 `http://127.0.0.1:19370/docs`
- 数据库端口 `17870`

| 账号 | 演示密码 | 工作权限 |
|---|---|---|
| analyst | analyst-demo-24 | 导入 CSV、运行分析、导出工作稿 |
| reviewer | reviewer-demo-24 | 复核、设置和停止投递、导出 |
| viewer | viewer-demo-24 | 浏览结果、导出已批准的报告、查收投递 |

原生 HTML/CSS/JavaScript 前端与 Nginx、FastAPI、Python worker、PostgreSQL 16 和 Redis 组成五服务 Compose。`backend/src/services/domain.py` 存放业务算法，`domain.json` 定义字段与验收口径，`frontend/src/pages` 为业务页面。更新任一侧源文件后，用 `docker compose up -d --build` 重建对应镜像。`backend/src/constants/enums.py` 和 `frontend/src/constants/enums.js` 定义角色及运行状态。`.env` 支持前端、API、数据库端口、演示 seed 开关和 JWT 密钥。首次部署到非演示环境时更换演示身份及 JWT/数据库凭据。

`docker compose down` 停止服务并保留数据卷。现场数据和演示结果可以在各自版本中并存。
